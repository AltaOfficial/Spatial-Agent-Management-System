# Extension

> Draft v0, not settled. Source: the SAMS Notion workspace (Domain glossary, Overview, User Flows, Architecture).

A distributable package that registers new [object](object.md) types and binds them to real capability. The extension is the unit of the marketplace.

## Notes

- The marketplace comes after the MVP, but the extension boundary should exist in the data model early.
- **Milestone 4, "third-party objects,"** proves the extension model.
- Notion's draft foundation layers list the extension API's shape as an architecture decision, because boundaries are expensive to move once code exists.
- User flows still to write: "install something from the marketplace" (v3) and "publish an extension" (v3).

## Open decisions

- [How fine-grained is an object?](open-decisions.md#1-object-granularity) The answer shapes the extension API.
